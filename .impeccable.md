## Design Context

### Users
Personal Mac utility for a Russian-speaking user accustomed to Windows Win+V. Primary task: invoke history from the keyboard and immediately paste a previous text or image into the current app. At least 100 entries; menu bar access is secondary.

The user now intends an international version. All app-owned visible text, menus, errors, accessibility labels and relative timestamps must be English regardless of system language. Clipboard contents and external app names retain their original text.

### Brand Personality
Quiet, immediate, familiar. Product name: Clipscreen. The window heading is the single word Clipscreen.

### Aesthetic Direction
The user explicitly confirmed native macOS minimalism: a compact list, automatic system light/dark appearance, and minimal controls. Use AppKit, system typography, a compact floating panel, readable text excerpts and image thumbnails. Windows clipboard is the interaction reference; CopyClip is the user's negative usability reference.

### Design Principles
1. One shortcut opens history; arrows and Return complete the main task.
2. Show recognizable content before metadata; avoid decorative interface elements.
3. Preserve the source app and insertion point; dismiss on Escape or outside click.
4. Surface permission, persistence, and paste failures with an actionable explanation.
5. Use native macOS accessibility, system colors, and familiar focus behavior.
6. Clip backdrop materials as well as foreground content. Use native Liquid Glass on macOS 26, a correctly masked standard material on earlier versions, and an opaque system surface with Reduce Transparency.

### Concrete panel constraints
430 × 590 pt default footprint; 18 pt panel corners; 16 pt main insets; 76 pt rows with 4 pt separation; 48 × 48 pt thumbnail slots; 12 pt thumbnail-to-text gap; 5 pt title-to-metadata gap; system title 17 semibold / content 13 regular / metadata 11 regular. Two-line, truncated text previews and rounded 10 pt selection outlines. No full-content hover tooltips.

### Icons and resize behavior
Use original vendored Lucide SVGs from `Resources/Lucide` for app-owned icons, including the menu bar and screenshot editor; do not substitute SF Symbols or redraw the paths. Action icons are 16 pt inside 28 pt hit targets, with 4 pt gaps. The header contains only the title, capture and Pin; do not repeat the global shortcut or add a settings menu. Settings remain in the macOS menu bar. Pin is the rightmost header and row action. Active pin/filter states have an outline and fill, plus accessible state. Hover, press and active state share one 6 pt rounded surface drawn inside the button bounds; never stack a native bezel over a layer background. The resize grip draws at most 12 pt inside a 22 pt target. Preserve the top-left window anchor during corner resizing; persist geometry at drag completion and let AppKit coalesce display updates.

### Screenshot editor controls
Retain the filled rectangle tool. Use the same Lucide square geometry for outline and solid-fill tools; the local filled SVG changes only fill to currentColor, not its path. Tool targets are 30 pt; preset colors are 24 pt. Custom color uses a permanent rainbow ring with a plus in a 30 pt target and opens the standard color panel. Width is available in right-click menus on tools and annotations; do not add a separate toolbar width dropdown. Tool buttons expose current width in their tooltip and accessibility value, with Shift-F10/Show Menu access. Remember widths per tool for the current editor session; preserve reversible annotation edits. Filled rectangles have no outline width. Below 720 pt, use an 80 pt toolbar with colors on its second row; otherwise use a single 44 pt row. Reserve toolbar height above the canvas.
