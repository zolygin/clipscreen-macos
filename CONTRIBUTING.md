# Contributing to Clipscreen

Thank you for your interest in contributing to Clipscreen!

Clipscreen is a lightweight, zero-dependency native clipboard manager for macOS built with Swift and AppKit.

## Getting Started

1. **Prerequisites**:
   - macOS 13.0 or later
   - Xcode 26 or compatible Command Line Tools with the macOS 26 SDK (`swiftc`). The macOS 13 deployment target is separate from this build-SDK requirement.
   - No external third-party dependencies or package managers required.

2. **Verify Environment**:
   Run the test and verification suite:
   ```bash
   bash scripts/check.sh
   ```
   This runs static type-checks, executes the test suite in an isolated pasteboard environment (without altering your clipboard), and verifies `Info.plist`.

3. **Check UI Scenarios**:
   To render and test isolated UI preview states:
   ```bash
   bash scripts/check-ui.sh
   ```

4. **Building Development App**:
   To compile a local debug `.app` bundle:
   ```bash
   bash scripts/build-app.sh
   open .build/Clipscreen.app
   ```

## Design & Architecture Guidelines

- **Zero Third-Party Dependencies**: All features are implemented using pure Swift and Apple SDK frameworks (AppKit, CoreGraphics, ApplicationServices).
- **Privacy First**: Clipscreen operates completely offline. No network requests, telemetry, or remote analytics are permitted.
- **Sensitive Data Filtering**: Always respect system privacy types (`org.nspasteboard.ConcealedType`, `AutoGeneratedType`, `TransientType`, 1Password).
- **Native Look & Feel**: Follow Apple Human Interface Guidelines and project design principles documented in [.impeccable.md](.impeccable.md) and [docs/UI-UX-REVIEW.md](docs/UI-UX-REVIEW.md).
- **Localization**: App-owned UI elements, menus, errors, and system labels are in English. User-copied content and external process names retain their original text.

## Pull Requests

1. Fork the repository and create your branch from `main`.
2. Ensure `bash scripts/check.sh` passes with zero errors and all tests pass.
3. Keep pull requests focused on a single feature or bug fix.
4. Describe your changes and test scenarios clearly in the PR description.

## Distribution tooling

`npm run dist:check` performs local readiness checks without building or uploading; `npm run check:dist` runs isolated release-wrapper tests with mocked external tools. These optional commands require Node.js 22+ and use built-ins only. `npm run dist` is a full optimized, signed/notarized distribution build and uploads the DMG to Apple. Follow the repository build-authorization policy before running it. Setup and verification limits are in [DISTRIBUTION.md](docs/DISTRIBUTION.md).
